几个文件同时跑: 数量是机器核数的一半, 最多 4 个, 带
--headed
或
--bail
时一次一个 (
--workers
设这个数). 每个 worker 构建到它自己的目录 (
.acde/test
、
.acde/test-2
……). 失败的测试会再跑
--retries
次, 每次都在全新的会话上, 有它自己的超时; 后面有一次尝试通过, 测试就通过, 并有一行写着
passed on attempt 2 of 2 (flaky)
.
用
-t
时, 没有测试匹配的文件会被跳过, 也不算失败 (
acde test: e2e/approval.e2e.ts: no test matches -t "saves", skipped
); 所有文件里都没有测试匹配时,
acde test
打出
acde test: no test matches -t "<pattern>" in <n> files
, 退出码 1.
每个文件跑的时候打出它自己那次
bun test
的输出; 几个文件同时跑时, 一个文件的输出在它跑完时整块打出. 整次运行以两行汇总结束, 一行数测试, 一行数文件:
acde test: 5 tests ran: 4 passed, 1 failed, 1 not run (skipped, todo, or not matched by -t)
acde test: 2 files, 1 passed, 1 failed: e2e/notes.e2e.ts
what the failing tests left: /path/to/notes/.acde/test-results
第一行数的是跑过的文件里的测试: 跑了多少、通过多少、失败多少, 以及 (有的话) 多少没跑 (
test.skip
、
test.todo
, 以及被
-t
排除的测试). 这些数字来自
bun test
给每个文件写的报告. 没留下报告的文件 (它没能载入, 或它那次运行被杀掉了) 不计数, 只列出名字:
; not counted: e2e/broken.e2e.ts (bun test left no report: the file did not load, or its run was killed)
.
第二行数的是跑过的文件,
不是测试
: 一个文件里的测试全都通过, 这个文件才算通过. 它列出失败的文件, 适用时还加上
, <n> skipped (no test matches -t)
和
, <n> not run (--bail)
. 有失败的测试留下了文件时, 它下面才有缩进的那一行.
没有失败时退出码是 0, 否则是 1.
