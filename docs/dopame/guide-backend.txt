Windows 上
Windows 上 一节的链接
同一份构建产物在 Windows 上也能跑, 那里后端同样不开 TCP 端口, 也不开命名管道. 运行时怎么连到它, 看是什么在跑它:
Bun
: 和 macOS、Linux 上一样,
listen(P)
变成一个 socket 文件
P.sock
. 它所在的目录 (
ACDE_APP_SOCKETS
) 每次启动后端时重新建, 只有当前用户和系统能打开.
Node.js
: Node.js 在 Windows 上不能听 socket 文件, 所以根本没有东西在听. preload 留住调了
listen(P)
的那个服务器, 运行时通过一条通到后端进程的私有管道, 把每个连接 (HTTP 请求和 WebSocket 升级) 交给它. 后端拿到
ACDE_APP_CHANNEL=fd
, 没有
ACDE_APP_SOCKETS
. 在这之前的 acde 构建的后端在 Windows 上不会被启动; 日志里写
not started: acde-listen.js does not support the Windows channel (built by an older acde: acde build it again)
.
在 Windows 上停后端时, 运行时请它自己关闭: 它不再接新连接, 做完进行中的请求, 然后退出; 3 秒后运行时结束它, 连同它启动的进程.
