安装
安装脚本装上 acde (命令行工具、工程模板和 SDK), 连同和它配对的运行时 acdert, 你的应用由它来跑. 不经 npm, 不需要 root. 见
运行时
.
交给编码 agent
交给编码 agent 一节的链接
把这句话交给你的 agent:
Read https://pkgs.dopame.ai/acde/install.md and follow it to set up acde on this machine.
它读到的那一页会让它检查 Bun 或 Node.js、跑下面的安装脚本、给自己装上 acde skill, 再汇报哪些已经就绪. 见
编码 agent
.
先决条件
先决条件 一节的链接
acde 跑在你已有的 JS 运行时上, 二选一:
Bun
1.4 或更新
Node.js
22.3 或更新
两个都有时 acde 用 Bun. 安装脚本不会替你装它们.
acde test
(端到端测试) 只能在 Bun 上跑. 只有 Node.js 时, 其余命令都能用.

检查
检查 一节的链接
先新开一个终端.
安装脚本改的
PATH
只对之后新开的终端生效, 所以在刚才跑安装的那个终端里,
acde
会报
command not found
. 一定要用那个终端的话, 先运行安装脚本打出来的最后一行 (
export PATH=…
, PowerShell 里是
$env:Path = …
).
在新终端里运行:
终端窗口
acde
doctor
它检查
acde dev
和
acde test
需要的东西: PATH 上的 acde、Bun 和 Node.js、运行时 (找到没有、能不能跑、和这一版 acde 是否配对, 以及运行时自己对它的文件和 GPU 的检查, 它会在 GPU 上画一帧测试图) 等等. 每行以

、
warn
、
error
或

开头, 每个问题下面跟一行以

开头的修法, 最后一行说是不是都齐了. 见
检查环境
.
acde --version
只打版本: acde、构建它时用的 SDK 和契约级别, 以及它找到的运行时和运行时的版本、契约级别.
运行时
运行时 一节的链接
acde dev
和
acde test
要在运行时 acdert 里跑你的应用. 安装脚本把和这一版 acde 配对的那一版 acdert 装在它旁边: 二进制是
bin/acdert
(Windows 上是
acdert.exe
), 它的 host 文件是
bin/app/
, 两样都按那个版本的
SHA256SUMS
核对过. 配对关系记在 acde 的每个版本里, 所以装 acde 的指定版本 (安装脚本的
--version X.Y.Z
, Windows 上是
-Version X.Y.Z
) 也就装上那个版本配对的运行时. 运行时装不上时 (你的平台没有构建, 下载或校验失败), 安装脚本什么都不装, 原来有的保持不动. 在 Dopame 虚拟机里,
acdert
已经在 PATH 上.
acde 按这个顺序找运行时:
ACDERT
: 一个 acdert 二进制的路径, 或 PATH 上的名字;
安装脚本装在 acde 旁边的 acdert;
PATH 上的
acdert
.
都没有时,
acde dev
停下并说明原因,
acde doctor
说出它找过哪些地方、该怎么办.
运行时只在 GPU 上绘制页面, 需要能用的 GPU (macOS Metal, Windows DirectX 12, Linux Vulkan). 在 Linux 上, 这指的是这台机器的 GPU 的硬件 Vulkan 驱动 (Mesa: Arch 上是
vulkan-intel
或
vulkan-radeon
, Debian、Ubuntu 和 Fedora 上是
mesa-vulkan-drivers
; NVIDIA: 厂商的驱动); 软件渲染器不算. 没有它,
acde dev
一启动就失败, 日志里有一行以
web layer unavailable:
开头, 写着
no usable Vulkan driver was found: install the GPU's Vulkan driver …
: 装上驱动, 再确认
vulkaninfo --summary
列出了这块 GPU. 启动任何东西之前,
acde doctor
的
gpu
那项就会以错误报出同一行.
