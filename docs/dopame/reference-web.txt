Web 兼容性
acdert 的渲染器是自研的 (不是 Chromium), 页面的 JS 跑在它内嵌的 V8 里. 原则是
标准接口和浏览器完全兼容
: 行为、签名、事件、错误都照规范; 做不到的就是缺口, 不拿长得像的私有版本顶替. 下面列出值得知道的地方.
源
源 一节的链接
所有应用页面的源都是
http://acde.local
. 每个应用的存储是分开的分区, 互相看不到.
存储
存储 一节的链接
接口
说明
localStorage
同一应用的所有窗口共用; 5 MiB 配额; 别的窗口改了收
storage
事件
sessionStorage
每个窗口自己的, 只在内存;
location.reload()
之后
不
保留 (和浏览器不同)
IndexedDB
完整实现, 存在 SQLite 里; 用 promise 包装的库 (idb 等) 行为和浏览器一致
Cache API
caches
支持
cookie
同源 (自己的后端) 的照常存取; 跨源请求不带也不存 cookie
navigator.storage
estimate()
;
persist()
总是
true
;
getDirectory()
是私有文件系统 (OPFS)
数据在
$XDG_DATA_HOME/acde/storage/app-<id>/
.
网络
网络 一节的链接
fetch
、
XMLHttpRequest
、
WebSocket
、
EventSource
都支持.
同源路径和
localhost
送到应用自己的后端, 见
后端
.
访问别的主机走系统的 DNS 和网络, 证书照常校验, 并按系统的设置走代理: 会话里设了
http_proxy
、
https_proxy
或
all_proxy
时, 只看这些变量 (和
no_proxy
); 否则用系统的代理设置 (Windows: 用户的 Internet 设置, 包括配置脚本和自动检测; macOS: 网络设置; Linux 没有别的来源).
localhost
、回环地址和应用自己的后端总是直连. 不支持代理认证和
https://
代理. 响应不自动解压 (不发
Accept-Encoding
).
跨源请求照浏览器的规则: 带
Origin
、CORS 预检、响应头过滤、
no-cors
的不透明响应.
被禁的请求头 (
Host
、
Cookie
、
Origin
、
Referer
、
Sec-*
……) 设了也不发.
同步 XHR 只能读应用自己的文件.
外部资源
外部资源 一节的链接
图片 (
<img>
和 CSS 里的图片)、样式表 (
<link rel="stylesheet">
) 和字体可以从别的主机加载, 和在浏览器里一样: 图片和样式表不需要 CORS, 字体要有允许这个页面的
Access-Control-Allow-Origin
, 样式表只接受 2xx 的
text/css
响应. 它们出现在
acde network
里, 种类是
image
、
stylesheet
和
font
; 加载失败的会有一条控制台错误
Failed to load resource: <url>: <reason>
.
<link rel="stylesheet">
在它的样式表取到并生效之后触发
load
, 取不到时触发
error
(它
@import
的样式表取不到时也一样); 从这时起
link.sheet
和
document.styleSheets
里有这张样式表. 别的主机来的样式表, 它的规则 (
sheet.cssRules
) 会抛
SecurityError
, 除非这个 link 带
crossorigin
, 并且那个主机用
Access-Control-Allow-Origin
允许这个页面.
不能从别的主机
import
ES 模块
(
module … is not a local file
): 把依赖的代码打进应用里. (经典
<script src>
可以从别的主机取.) 要在没有网络时也能用的应用, 把图片、样式和字体也打进去.
脚本
脚本 一节的链接
支持经典
<script>
、
type="module"
和
type="importmap"
.
文件选择器
文件选择器 一节的链接
showOpenFilePicker
、
showSaveFilePicker
、
showDirectoryPicker
、
<input type="file">
弹系统的对话框, 见
文件与文件夹
.
拖进窗口的文件和文件夹按标准的方式送达:
dataTransfer.files
, 以及
dataTransfer.items[i].getAsFileSystemHandle()
给的只读句柄. 文件夹和超过 64 MiB 的文件不在
files
里, 用句柄. 见
拖进来的文件
.
媒体
媒体 一节的链接
Audio
/
AudioContext
支持. WebGPU 目前只在 Linux 上有.
<video>
能放系统自己的解码器打得开的东西, 所以各平台支持的格式不同: macOS 上 MP4 / QuickTime 能放, WebM 不能. 选源之前先问
canPlayType()
.
navigator.mediaDevices.getUserMedia()
需要配置里有
camera
/
microphone
能力, 并得到用户批准 (见
系统能力
). Windows 上不可用.
必需的能力在应用启动前批准. 还没问过的
可选
能力由
getUserMedia()
自己问, 用的就是
request('camera')
引出的那个提示; 两样都要的调用先问麦克风, 再问摄像头. 用户允许后这次调用 resolve, 用户拒绝时以
NotAllowedError
(
Permission denied
) reject; 之后的调用不再问.
navigator.permissions.query({ name: 'camera' })
(或
'microphone'
) 在用户回答之前回
prompt
, 被拒绝或批准被收回之后回
denied
; 用户回答时它的
change
事件触发. 用户允许之后, 回的是宿主系统自己对这个设备的权限 (系统也允许时是
granted
).
在没有声明这个能力的应用里, 查询回
denied
,
getUserMedia()
以
NotAllowedError
reject, 不出提示.
先判断约束: 没有设备能满足的请求以
OverconstrainedError
reject, 谁也不问.
对还没被允许的那一类设备,
enumerateDevices()
列出一个不带标签的条目.
要在没有真实摄像头或麦克风的情况下试页面, 用
ACDE_CAPTURE=fake
启动会话: 这时设备是
Fake camera
和
Fake microphone
.
暂不支持
暂不支持 一节的链接
<datalist>
、
<select>
的
appearance: base-select
、Web Worker、
crypto.subtle
、WebGL (
getContext('webgl')
和
getContext('webgl2')
返回
null
; 用 2D canvas, 或 Linux 上的 WebGPU)、OffscreenCanvas /
createImageBitmap
、Fullscreen API (
requestFullscreen()
以
NotSupportedError
reject; 应用窗口用
acde:window
的
requestState('fullscreen')
进全屏) 和指针锁定、
:target
、Storage Buckets、Service Worker.
与浏览器的差异
与浏览器的差异 一节的链接
alert()
画在窗口里;
confirm()
返回
false
,
prompt()
返回
null
.
navigator.userAgent
和
navigator.platform
在每个系统上都说是 Linux (
Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) acdert/<version>
和
Linux x86_64
), 编辑用的快捷键在哪里都用 Ctrl, 所以应用在每个宿主系统上的行为都一样. 要知道真实的系统, 读
acde:capabilities
的
platform
.
没有开发者工具: 用
调试工具
和
MCP
.
页面没有安全沙箱 (还没有系统调用级隔离): 不要运行你不信任的代码.
