命令行
acde <command> [参数]
出错时打一行
acde: <原因>
, 退出码 1. 参数错了 (
act
不认识的动作、
console
不认识的级别……) 会打一行, 指出哪里不对、该看哪个
acde <command> --help
, 比如
acde: console: --level loud: one of log, info, warn, error, debug, errors (acde console --help)
; 完整的用法只有不带命令的
acde
才打.
acde --version
(或
-v
) 第一行打出 acde 的版本, 然后是构建它时用的 SDK 版本和契约级别, 以及它找到的 acdert (先
ACDERT
, 再装在 acde 旁边的那个, 再 PATH) 和这个运行时的版本、契约级别.
acde --help
(或
-h
) 打出用法;
acde <command> --help
和
acde help <command>
只打出那个命令的. 不认识的命令或参数会打出一行, 说明哪里不对、该看哪个
--help
, 退出码 1. 颜色跟随
NO_COLOR
.
环境
环境 一节的链接
acde doctor
acde doctor 一节的链接
acde doctor [dir] [--json] [--online] [--fix [--yes]]
检查这台机器上
acde dev
和
acde test
需要的东西: PATH 上的 acde、Bun 和 Node.js、acdert (找到没有、能不能跑、跑的是不是这一版 acde 构建的契约级别、是不是和这一版 acde 配对的版本)、运行时自己的检查 (
acdert doctor
: 它的 host 文件、GPU, Linux 上还有显示环境)、正在跑的
acde dev
和它们在等的批准、
dir
里的工程 (默认是当前目录;
acde check
、这个平台、依赖、
.gitignore
里有没有
.acde/
), 以及给编码 agent 的 acde skill. 见
检查环境
.
选项
说明
--json
打一个 JSON 对象而不是一行行文字:
{"ok": …, "checks": [{"id", "title", "status", "summary", "fix", "repair"}]}
; 带
--fix
时还有
"fixed"
--online
再问
pkgs.dopame.ai
(或
ACDE_DIST
) 有没有更新的 acde
--fix
检查完修 acde 能修的: 有的直接修, 其余的问过再修; 修完再检查一遍. 见
能修的就修
--yes
和
--fix
一起用: 本该先问的修复不问就做
每项检查打一行
<状态> <检查>: <看到了什么>
, 有问题的下一行是
fix: …
, 最后一行数错误和警告. 状态是
ok
、
warn
、
error
或
skip
(没检查: 这里没有工程, 或者它依赖的检查失败了). 有一项是错误时退出码是 1, 否则是 0. 给的
dir
里没有 acde 工程算错误.
带
--fix
时, 报告之后对每个修复打
fixing: <做什么>
、它跑的东西的输出, 然后是
fixed: <做什么>
或
failed: <做什么>: <原因>
; 没被允许的打
skipped: <做什么>
; 最后打
acde doctor: after fixing:
并再检查一遍, 退出码看第二遍. 没有能修的时说
acde doctor: nothing here it can fix; the fix lines say what to do
. 只给
--yes
不给
--fix
是错误.
工程
工程 一节的链接
acde new
acde new 一节的链接
acde new [dir] [--template T] [--id ID] [--label NAME] [--backend] [--install] [--git] [--pm PM] [--yes]
新建工程. 在终端里会问缺的信息;
--yes
或不在终端里时什么都不问 (这时
dir
必填, 模板默认
html
, 不装依赖、不建仓库).
参数
说明
--template
html
desktop
react
vue
svelte
solid
preact
vanilla
next
nuxt
sveltekit
astro
--id
/
--label
应用 id 和显示名
--backend
带一个后端 (只对
html
)
--install
装依赖
--git
git init
并做首次提交 (配了 git 用户名和邮箱时)
--pm
bun
npm
pnpm
yarn
, 决定工程跑在 Bun 还是 Node.js 上
acde check
acde check 一节的链接
acde check [dir] [--platform windows|macos|linux]
检查配置 (id、入口、图标、服务模块、框架) 和 SDK 的清单规则, 或手写包的清单和入口文件, 并对照清单检查
acde:
导入. 它在 stderr 上打出
error:
、
warning:
和
note:
行, 只有存在错误时退出码才是 1.
note:
标出检查放行但核实不了的导入, 即
桌面服务
的一个不是服务自己名字的命名空间:
note: src/main.js:1: app "notes": acde:timer resolves only if the service Notes lists ("clock") provides the "timer" namespace
.
--platform
再拿应用声明的能力和那个平台有的对照检查, 在那里跑应用的每种方式各查一次 (
desktop
和
standalone
, Linux 上还有
session
):
平台没有的必需能力是错误:
error: windows (desktop): app "notes" requires network, which this mode lacks
.
平台没有的可选能力只是一条提示, 不算错误:
note: windows (desktop): app "notes" runs without optional camera, which this mode lacks
.
必需的能力一个都不缺时, 最后一行是
ok: linux (session, desktop, standalone): every required capability is there
.
acde build
acde build 一节的链接
acde build [dir] [--out DIR]
构建到
DIR
(默认
.acde
). 相对的
--out
相对被构建的工程. 先检查
acde:
导入, 和
acde check
里一样 (有错误就停止构建,
note:
只打出来), 产物的清单会再检查一遍.
acde install
acde install 一节的链接
acde install [dir] [--out DIR]
构建后装进
$XDG_DATA_HOME/acde/packages/<id>
; 没设
XDG_DATA_HOME
时是
~/.local/share/acde/packages/<id>
(Windows 上是
%USERPROFILE%\.local\share\acde\packages\<id>
). 见
本机安装
.
acde dev
acde dev 一节的链接
acde dev [dir...] [--out DIR] [--app ID] [--desktop ID|DIR] [--headless]
构建、启动 acdert、改了就重建并重载. 见
acde dev
.
运行中的会话
运行中的会话 一节的链接
这些命令要连上一个跑着的
acde dev
开发会话, 都接受
--session <pid>
.
<web>
是一张页面:
acde webs
列出的 web 名、应用 id 或
desktop
;
<ref>
是
acde inspect
或
acde query
给元素的编号, 比如
w1.12
, 或一个窗口, 比如
w1
. 见
调试工具
.
命令
说明
acde webs
页面列表
acde eval <web> <code|->
在页面里执行, 打印 JSON
acde shot <web> [-o FILE]
窗口截图, 默认
./<web>.png
acde screen [-o FILE]
整屏截图, 默认
./screen.png
acde inspect [--window W] [--find TEXT] [--all] [--offscreen]
屏幕的文字形式
acde query <selector> [--window W] [--ref REF] [--limit N]
CSS 选择器匹配的元素, 每个带 ref
acde act <ref> <action> [arg]
对一个 ref 做动作
acde console [--web W] [--level L] [--since S] [--follow]
页面日志和错误;
--since reload
或
--since N
acde network [--web W] [--failed] [--since S] [--follow]
页面请求;
--since reload
或
--since N
acde permissions
等待回答的批准提示和已做的决定
acde allow [<prompt id> | <app> <capability>] [--all]
允许一个等待中的批准提示
acde deny [<prompt id> | <app> <capability>] [--all]
拒绝一个等待中的批准提示
acde revoke <app> <capability>
收回一个决定
acde stop
结束开发会话和它的 acdert, 见
结束
acde mcp [--session PID]
stdio 上的 MCP 服务器, 见
MCP
选项
说明
--window
inspect
、
query
: 用这个窗口 (
w1
), 而不是焦点窗口
--ref
query
: 只在这个元素 (
w1.12
) 下面找
--limit
query
: 最多列出这么多个元素 (1 到 3000, 默认 600)
--all
inspect
: 每个没有标
[minimized]
的窗口, 以及被
opacity: 0
或
visibility
隐藏的元素.
allow
、
deny
: 每个等待中的提示
acde query
打出
N in <window>:
和每个元素一行, 或者
nothing in <window> matches "<selector>"
; 两种情况退出码都是 0.
acde act
打出它做了什么、变了什么, 动作没做成时退出码是 1 (这时只打一行原因).
acde permissions
打出两块, 退出码 0:
pending:
2  notes  fs.documents  (launch)
decisions:
notes  fs.downloads  granted
pending 的一行是
<prompt id>  <app>  <capability>  (<reason>)
, 其中 reason 是
launch
(应用启动前问的) 或
request
(运行中的应用问的); decisions 的一行是
<app>  <capability>  <granted|denied>
. 空的块是
pending: none
或
decisions: none
.
acde allow
和
acde deny
回答此刻在等的提示. 不带参数时回答唯一在等的那个提示; 有几个在等时一个都不回答, 把它们列出来, 退出码 1.
<prompt id>
指一个提示,
<app> <capability>
指那个应用关于那个能力的提示,
--all
指每个在等的提示. 每回答一个提示, 打出
allowed <app> <capability> (prompt <id>)
或
denied <app> <capability> (prompt <id>)
. 没有提示在等, 或没有匹配的, 就打出一行说明 (
acde: no approval prompt is waiting
、
acde: no approval prompt 5 is waiting (waiting: 2)
), 退出码 1.
acde revoke <app> <capability>
打出
revoked <app> <capability>
; 没有这个决定时它会说明, 退出码 1.
应用在等批准而没有页面在跑时,
acde webs
在空表后面给每个提示打一行:
<app> waits for approval of <capability>: acde allow (or acde deny)
. 见
批准
.
编码 agent
编码 agent 一节的链接
acde skills [install|remove|path] [--agent ID,...] [--dir DIR] [--copy]
命令
说明
acde skills
acde skill 装在哪些地方, 每一处是不是最新的
acde skills install
把 skill 链接进
~/.agents/skills
和找到的每个 agent 的 skills 目录
acde skills remove
从这些地方删掉,
install
建的、现在空了的目录也删掉
acde skills path
打印 acde 安装目录里 skill 的目录
选项
说明
--agent
只给这些 agent (逗号分隔的 id, 如
claude-code
、
codex
、
cursor
), 而不是找到的那些
--dir
改用这个 skills 目录; skill 装进
DIR/acde
--copy
拷贝而不是链接 (只用于
install
)
见
编码 agent
.
测试
测试 一节的链接
acde test [dir|file...] [--headed] [-t PATTERN] [--desktop ID|DIR] [--timeout MS] [--bail] [--trace] [-u]
[--workers N] [--retries N] [--video[=on]]
参数
说明
--headed
开窗口 (默认 headless)
-t
,
--test-name-pattern
只跑名字匹配的测试
--desktop
应用跑在这个桌面里
--timeout
每个测试的超时, 包括启动它的会话的时间 (毫秒, 默认 60000)
--bail
第一个失败就停
--trace
每个测试都留
trace.html
-u
,
--update-screenshots
重写截图基线
--workers
同时跑几个测试文件 (默认: 核数的一半, 最多 4; 带
--headed
或
--bail
时是 1)
--retries
失败的测试再跑这么多次, 每次都在全新的会话上; 后来通过的测试报告为 flaky (默认 0)
--video
给失败的测试留下
video.png
, 一张屏幕的动画 PNG;
--video=on
给每个测试都留
运行结束时有一行数测试 (
acde test: 5 tests ran: 4 passed, 1 failed
), 最后一行数文件 (
acde test: 2 files, 1 passed, 1 failed: e2e/notes.e2e.ts
); 见
端到端测试
.
