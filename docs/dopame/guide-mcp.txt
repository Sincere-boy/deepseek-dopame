MCP
acde mcp
是一个 stdio 上的
MCP
服务器, 把
调试工具
和更多能力交给 AI agent: 它能自己启动一个
acde dev
开发会话, 看屏幕、点按钮、读控制台、截图, 用来开发和验证你的应用.
这些事 agent 用普通的
调试命令
也都能做, 不用任何配置;
acde skill
会教它怎么用. 你的 agent 用工具比用 shell 顺手时再接 MCP.

acde mcp

作用
doctor
像
acde doctor
一样检查这台机器能不能跑
acde dev
;
start
失败时先调它
doctor_fix
像
acde doctor --fix
一样: 检查, 修 acde 不用问就能修的, 再检查一遍. 要下载、安装或结束进程的修复它只点名: 由用户在终端里跑
acde doctor --fix
(会问), 或同意跑
acde doctor --fix --yes
. 它的
dir
必须在工作目录里

/

/

permissions
/
answer
/
revoke
列出等待回答的批准提示和已做的决定、允许或拒绝一个等待中的提示、收回一个决定, 见
批准

选会话的规则: 钉住的; 否则
start
起的; 否则按工作目录挑.
应用必需一个要用户批准的能力时, 在它的提示得到回答之前不开窗口. 这时
start
和
webs
回一张空表, 加上每个提示一行:
notes waits for approval of fs.downloads: the answer tool allows or denies it
.
answer
接受

permissions
列出的
app
和
capability

只跑一个应用的会话里, 关掉唯一的窗口 (对
w1
用
act
做
close
) 会结束这个会话, 这是有意这样设计的. 这次调用成功, 它的回答会说明这一点:
closed w1; acdert exited with it, so acde dev 4242 ended
. 下一次调用失败, 并说会话已经停了 (
start
起的会话是
the acde dev started here (pid 4242) stopped; last output: …
, 在别处启动的会话是
acde dev 4242 stopped; no acde dev is running (…)
). 要继续就再跑一次
start
. 别的动作做到一半运行时没了, 就会失败, 报
acdert closed the connection
; 步骤里关掉了那个窗口的
run
也是这样, 因为它那些步骤的回答丢了, 所以要用
act
来关.

、
clock
、

和

app.mouse
/
app.keyboard
、
app.clock
、
app.answerDialog
和
app.resize

时间、对话框和页面准备
.
