# 桌面窗口与输入区布局修复

用户反馈 Dock 遮挡输入区，窗口也无法拖动。复核发现两个独立原因：

1. 单应用调试留下普通窗口位置 `[0,0,1361,835]`，而桌面实际工作区为 `[0,34,1361,715]`。标题栏藏在顶部菜单栏下，窗口底部伸入 Dock 区域；窗口本身的模式仍为 free，并非被锁定。
2. 原版输入区使用底部 sticky 布局，acdert 在缩放窗口或滚动长历史时可能将它留在可见区域之外。

修复保持在独立适配层：默认内容尺寸改为 1120×600，显式使用系统标题栏；本机仅清除该应用过期的位置记录，不影响会话、工作区和其他应用。恢复的窗口若大于桌面工作区，会使用系统 filled 状态适应工作区。

输入区改为按窗口视口定位，同时在原对话滚动容器中留出等高空间。适配只依赖上游稳定的 data 属性，不使用构建产生的 CSS 类名；保留原滚动容器、英雄页和视图自带的 composer overlay。

## 真实运行验证

在打开已有对话的桌面会话中运行：

```sh
npm run test:layout
```

脚本通过当前安装 acde 的公开 driver API 连接运行中的会话，不使用模拟 DOM，也不发送模型请求。

- 初始普通窗口位于 `[120.5,101.5,1120,632]`，标题栏和底边均处于工作区内。
- 在真实系统标题栏按下并拖动，窗口横向移动 20 像素。
- 960×520、1120×600 两档尺寸下，分别滚到历史顶部、中部、底部，输入框和发送按钮均未越出视口。
- filled 工作区模式与恢复普通窗口均通过相同边界检查。
- 中文输入“窗口布局验证”成功，随后清空，未发送消息。

验证脚本最终将窗口留在可拖动的普通状态。
