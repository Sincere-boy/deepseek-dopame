# DSH 协作工作区插件

在同一个 DSH Host 内管理组织者与多个独立节点会话，以固定流程图调度任务。群聊、流程图和节点详情直接嵌入 DSH 左侧的「协作工作区」入口，可在 Dopame OS 内使用，无需额外网站或升级 DSH。

## 启动与使用

在应用根目录安装依赖、准备 Harness 后运行：

```sh
npm run dev
```

从 Dopame 桌面打开 **DeepSeek Harness → 协作工作区 → 新建工作区**，填写工作区名称和项目绝对路径。插件会创建一个组织者会话和每节点一个会话；所有节点在所填项目目录工作。

- 「发送给组织者」用于讨论、询问进展。组织者可以读取状态；用户明确要求执行时，它可调用 `graph_start_run`。
- 「启动流程」直接执行输入的完整任务，无需组织者再确认。默认流程为开发 → 评审 → 测试 → 完成，评审拒绝或测试失败会返回开发。
- 图中显示节点状态与允许的连线，绿色连线表示本轮已经报告的路径。点击节点查看职责、最近报告摘要，并可打开原始 DSH 会话查看工具调用和详细过程。
- 需要人工处理或执行异常时，填写意见后点击「提交处理意见并重试」。这会为当前节点创建新的执行标识。
- 「取消任务」先进入正在取消，确认会话停止后才允许新任务。

节点同时显示业务状态与会话状态，例如「执行中 · 排队」「已完成 · 空闲」。后端每 5 秒通过 DSH `sessionController.list` 和 `control` 检查运行标记、消息队列与后台任务；查询失败或结果过旧显示「状态未知」，不按停止处理。只有持续空闲、没有队列和运行中的后台任务、且 300 秒没有进展，才显示卡住提示。

卡住属于健康提示，不会自动撤销本次执行，也不会代写 `pass`。本次执行的有效结果仍可上报；用户点击「提交处理意见并重试」时，后端再次确认会话空闲，再创建新执行 ID。正在运行、排队或有后台任务时拒绝重复派发。当前不自动唤醒或重发任务，避免重复执行工具副作用。

群聊在上、状态图在下，均使用内容区的完整宽度；向下滚动查看图，也可点击「状态图」单独查看。群聊是协作事件的消息视图，展示用户消息、任务启动内容和各会话的最终文字回复；不直接展示完整原始事件日志或工具调用轨迹。投递和节点流转记录见「事件时间线」，完整执行过程见节点会话。

标题、工作区工具栏和视图标签位于内容滚动区之外；聊天、消息列表和图分别限制绘制层级与裁剪边界，防止滚动内容遮挡顶部控件。输入区和节点按钮仅在所属区域内提高点击层级。创建表单的操作区随表单正常滚动。

工作区列表区分「正在加载」「加载失败」和「暂无工作区」。连接失败时保留已加载的列表，可点击「重新加载」；恢复后错误自动清除。若后端连接仍被拒绝，可关闭并重新打开 DSH 应用，已有工作区保存在数据库内。

创建时可展开「流程图配置」编辑 JSON。配置字段为 `version`、`entry`、`nodes`；每个节点包含 `id`、`label`、`instructions` 和 `outcomes`（结果名 → 目标节点 ID，`null` 表示完成）。允许返工环，要求入口能到达所有节点，最多 20 个节点。工作区创建后图配置固定；更改流程时创建新工作区，历史事件仍按原图解释。目前通过 JSON 配置图，尚未提供拖拽编辑器。

## 调度边界

组织者负责理解需求，后端负责执行图。节点通过 `graph_report_result(execution_id, outcome, summary)` 提交业务结果，或通过 `graph_request_human(execution_id, summary)` 请求人工处理。身份取自实际调用工具的 DSH 会话；后端校验当前执行 ID、绑定会话与允许结果。普通聊天和模型口头表示完成不会推进流程。

报告仅代表提交结果。只有该执行对应的 DSH `turn/end` 确认完成，后端才沿图创建下一个节点任务；执行失败或没有报告时暂停处理。每个工作区同时只有一个活动节点，工作区之间可以独立运行，不支持同一图内并行分叉与汇聚。

插件拦截标准 `/api/session/prompt` 入口，拒绝直接向受管节点会话发消息；请在协作工作区提交任务或处理意见。组织者和普通会话保留原入口。这是同一 Host 中的协作约束，不是针对其他受信任 Host 插件、任意命令执行或外部修改数据库的安全隔离。多个会话共享项目文件，插件不自动创建 Git worktree。

## 事件、投递与恢复

`store.mjs` 使用 Node.js 内置 SQLite，将事件日志、工作区当前状态和待投递任务放在同一事务内。稳定的 `commandId` 保证命令重复提交不产生第二次状态变化；投递 ID 同时作为 DSH 的 `requestId`，投递结果不确定时使用同一 ID 重试，而不新建任务。

`index.mjs` 使用 DSH 的 `sessionController` 创建、投递和跟随会话。会话持久化事件中的 `source.rpcId` 将提示与执行准确关联。重启后重放历史事件并按事件序号去重；已有报告仍需等待对应执行结束。历史快照和空闲状态本身都不结算执行；缺少结束事件的中断任务由会话健康检测提示处理。真实的执行失败或无报告的正常结束仍进入「需要处理」。系统不会承诺工具副作用恰好发生一次，也不会自动重放已开始的文件修改。重试前应查看原会话和项目现状。

数据库位于 `$DSH_HOME/graph-collaboration/graph.sqlite`，在此应用内对应应用私有数据目录的 `harness/graph-collaboration/graph.sqlite`，不在代码仓库。运行中 SQLite 使用 WAL；备份时先停止应用，或使用 SQLite 一致性备份。页面通过现有同源鉴权连接访问 `/api/graph-collaboration`，不新增 TCP 端口。

`client.js` 使用 DSH 的共享 React 运行时与 `sidebar.panellist`、`main` 槽位；图的连线由 SVG 绘制，节点采用 HTML 按钮，确保 acdert 中的点击区域和键盘选择正常。`scripts/build.mjs` 将插件随运行时打包，`server.mjs` 将它链接到应用私有 profile，`src/dopame.patch.yml` 注册 Host 与 Client 插件。

## 验证

在应用根目录运行：

```sh
npm test
acde check
acde build
# 启动应用，并先在测试项目目录完成一次流程，再检查已有执行记录与真实 UI：
npm run test:graph -- <已完成工作区ID> /tmp/dsh-graph.png
# 通过真实按钮测试必填项、JSON 和图配置错误、创建绑定，以及宽/窄窗口上下布局：
npm run test:graph-create
# 注入断连，检查已有列表保留、加载失败提示和手动重试恢复（不创建工作区、不调用模型）：
npm run test:graph-load
# 检查滚动、缩放、下拉框和长表单的遮挡与真实点击命中，不调用模型：
npm run test:graph-layers -- <含聊天记录的工作区ID> /tmp/dsh-layering
```

`test:graph-create` 会在应用私有测试目录创建一个未启动任务的工作区并绑定四个会话，不调用模型。创建表单使用显式校验，错误直接显示在提交按钮上方，避免运行时原生必填校验没有提示时出现「点击无反应」。

`test:graph-layers` 覆盖 1120×600、760×520、960×600 窗口及填满工作区的视图，共 43 个场景；检查 328 处控件命中（数量随工作区状态变化）、内容边界与横向溢出，并保存截图。测试不创建工作区、不发送消息，结束后恢复原工作区。

`test:graph` 不创建工作区或调用模型；它检查已完成执行的会话绑定、合法流转、真实标准 prompt 入口的拒绝响应、SVG 节点与连线、打开节点会话、页面重载后状态和事件保持一致，并保存截图。默认选择本机名为「协作图端到端验证」的已完成测试工作区。

已实际验证默认三节点完成、评审退回后重新开发的五轮流转、组织者查询状态、请求人工及处理后恢复、取消确认，以及页面和 Host 重启后的持久化恢复。会话监控实测显示执行中，重复恢复请求返回拒绝；任务正常上报并结束后，流程完成，会话状态回到空闲。标准 prompt 入口允许组织者正常回复，并拒绝直接唤醒节点。

`npm test` 包含 27 项回归测试（7 项原有通信/生命周期测试，20 项协作测试），覆盖重复命令及创建重试、越权/迟到报告、非法结果、真实轮次结束、返工、人工处理、取消、历史快照时序、运行中/排队/后台任务/未知/缺失状态，以及卡住提示后有效 `pass` 仍可完成流程。真实模型验证均在应用私有测试项目目录内完成，不使用用户现有项目作为测试目标。
